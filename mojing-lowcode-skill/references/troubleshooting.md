# 平台坑清单与排查套路

> 全部为真实项目实踩验证。**不要重复试错**，直接按结论执行。

## 1. 事件与脚本

| 坑 | 结论 |
|---|---|
| 表单级 Gy新增后/AfterInsert | 不触发，自定义按钮提交不走表单级事件 |
| 按钮级事件源码导入 | 不执行，必须在设计器手动粘贴 |
| 按钮级"新增后/更新后" | 都要粘同一份 groovy（新建走 insert、编辑走 update） |
| 列表按钮自定义脚本/前后脚本 | 平台标记"待开发"，不可用；改数据走"表单+按钮级 groovy"路径 |

## 2. 表单控件

| 坑 | 结论 |
|---|---|
| 隐藏字段 display:false | 控件不渲染 = 不参与提交、出参填不进 → 后续拿不到值。必须 `hidden:true` + `display:true` |
| 日期控件被出参填充 | 提交值是数组 `[2026,10,29,0,0]` → 报"字段太长"；保存前 JS 转字符串 |
| 按钮 handle=back | 平台不认；用 `close` |
| 按钮"编辑"类型 | 不认出参初始化（新弹窗填数据必须"新增"类型） |
| batch 空行"序号 1" | `lineNums:1` 默认渲染的空模板行，不是数据 |
| 多 batch 同 model | 平台按 model 绑定数据 → 共享数据互相覆盖、每次打开结果变一次；换独立 model |

## 3. 列表 SQL 与卡片

| 坑 | 结论 |
|---|---|
| 自定义 SQL select * | 平台解析不了列清单，禁用 |
| SQL 结尾加分号 | 报错，不加 |
| "自定义 SQL 排序"栏填代码 | 报"操作失败"，排序写进 SQL 内部 |
| 卡片"全部"填任何条件（含 1=1） | 报"操作失败"；只有状态类卡片填条件 |
| 按钮显隐条件加 this. | 行内变量直接写变量名；`this.` 是列格式化语法 |
| 按钮显隐引用列没 SELECT | 列空 → 全行判同 → 按钮错显；隐藏列也要输出 |
| task_state CASE 中文值配字典/转换 | 不配任何转换（值不是字典编码） |
| 平台查询把条件拼 SQL 末尾报"未知列" | 外层包一层 `SELECT 列名... FROM (原SQL) t`（不能 select *） |

## 4. 传参链路

| 坑 | 结论 |
|---|---|
| 列表按钮出参用 inParams 格式 | 不生效，用手册 4.4.4 arguments |
| 入参类型选错 | UUID/文本参数选"字符串"，选"数值"传不进导致列表空 |
| 入参按同名列过滤 | SQL SELECT 出的同名列值必须与入参一致（详情页 project_id=任务头 id） |
| 列表头按钮 agentValue=${行列} | 取不到行数据；只能取入参/上下文，行数据走"行内按钮传 id → 入参"链路 |
| 跳转关联配置（list key） | 非必需，配了可能干扰，留空 |
| agentValue 列没 SELECT | 漏列取不到 → 参数空 |

## 5. 数据与业务

| 坑 | 结论 |
|---|---|
| 任务只建主记录不建拆分 | 管理端统计全 0/0、状态误判"已结束"、详情没单位 |
| 有补充材料但没完成填报 | 业务不自洽（补充材料=完成后退回补交）；演示数据必须补齐 |
| 逾期任务却有完成填报 | 不自洽（填了完成就不是逾期）；逾期演示 = 无完成字段 |
| material_status=delay | 废弃状态，全库改成 none（材料状态只留 无/待补充/已补充） |
| "取最新一条"子查询无空值过滤 | 完成记录（空正文）顶掉有值进度 → 最新进展空白 |
| pymysql 执行含 % 的 SQL | `%` 要写 `%%` 转义（占位符冲突） |
| 单位名显示成数字 ID | org_name 存部门 ID，列表要 join sys_depart |

## 6. 通用排查套路

1. **数据 vs 配置先分清**：查库确认数据在不在 → 再查配置（SQL 编码内容/JSON）→ 再看页面。
2. **F12 三查**：提交载荷（保存前 JS console.log(formData)）、getWidget 组件属性、SQL 返回行数。
3. **单测法**：JS 只加载一个子表/只留一个条件，定位是多组件互扰还是单点故障。
4. **写死测试**：跨页参数传不进时，先把 SQL 条件写死（能出数据=参数链路问题；写死也错=SQL 问题）。
5. **改库前确认**：UPDATE/DELETE 前先 SELECT 同条件看目标行数；删数据用软删（del_flag=1）优先。
6. **动数据恢复现场**：清数/改数前记录原 id 与关键字段，必要时可回滚。
